# ai-dev-daily-search

Мини-сервис: каждое утро ищет свежие **прикладные** новости про ИИ-разработку по мировым
источникам, курирует по строгим критериям и присылает **дайджест-пост от имени Армана**
(подача через выгоду читателя) в Telegram.

Статус: **работает на сервере автономно** — cron на mh-central, три захода
(04:00 / 04:30 / 05:00 UTC), отправка в 09:00 Астаны. Дайджест уходит ботом
`@businessman_news_bot` в группу «Вайбкодинг от Армана»; аварии — отдельным
адресатом владельцу в личку. Пропуск прогона замечает внешний сторож
(`server-watchdog`) по heartbeat-отметке — чек включён 2026-08-14.

## Как работает пайплайн

1. **Сбор** (`pipeline/collect.py`) — три живых источника:
   - **X.com** recent search (4 запроса, свежие твиты практиков) — 450 req/15мин
   - **Exa** нейропоиск (4 запроса, статьи/блоги с фильтром по дате)
   - **GitHub** search свежих репо (`created:>`)
   → `data/candidates.json`
2. **Курация** — отбор по критериям `prompt.md`: конкретика + прикладная выгода, анти-фильтр
   режет крипту/рекламу/хайп. Отбирается 3–6 материалов + «на радаре».
   Perplexity добирает свежие материалы с источниками, Claude отбирает по критериям
   и пишет тексты блоков. Внешний контент передаётся модели размеченным блоком данных
   с запретом исполнять инструкции изнутри.
3. **Отправка** (`pipeline/send_post.py`) — пост в Telegram-HTML от имени Армана, подача
   через выгоду читателя, через Telegram-бота в чат получателя.

## Запуск

```bash
cp .env.example .env    # подставить имя своего Key Vault и имена секретов
set -a && . ./.env && set +a

python3 pipeline/run_daily.py --dry-run   # весь путь, без отправки
python3 pipeline/run_daily.py             # боевой прогон
```

Флаги: `--dry-run` — пройти весь путь и показать пост, ничего не отправляя;
`--force` — отправить, даже если сегодня уже отправляли; `--now <ISO>` — подменить
текущее время для отладки; `--attempt N --attempts M` — номер захода за сегодня
(см. «Установка по расписанию»).

Отдельные шаги (для отладки): `pipeline/collect.py` — только сбор кандидатов;
`pipeline/send_post.py` — переотправка уже посчитанного `data/digest-<дата>.json`.

## Установка по расписанию

Сервис рассчитан на cron: пути внутри абсолютные, поэтому рабочая директория
не важна. Отправка в 09:00 Астаны = 04:00 UTC.

Запуск идёт через обёртку `ops/run-daily.sh`: она подхватывает конфигурацию из
`/etc/ai-dev-daily/ai-dev-daily.env` и накрывает прогон внешним `timeout`.

```cron
CRON_TZ=UTC
0  4 * * * /path/to/ai-dev-daily/ops/run-daily.sh --attempt 1 --attempts 3 >> ~/logs/ai-dev-daily.log 2>&1
30 4 * * * /path/to/ai-dev-daily/ops/run-daily.sh --attempt 2 --attempts 3 >> ~/logs/ai-dev-daily.log 2>&1
0  5 * * * /path/to/ai-dev-daily/ops/run-daily.sh --attempt 3 --attempts 3 >> ~/logs/ai-dev-daily.log 2>&1
```

**Три захода, а не один.** Разовый сбой в 04:00 — моргнувшая сеть, 5xx от
провайдера — иначе стоил бы целого дня. Дубль исключён идемпотентностью:
второй заход видит отметку об отправке и выходит с кодом 0, ничего не сделав.
Алёрт и отметку `failure` даёт **только последний** заход: иначе один инцидент
превращается в три сообщения, а промежуточный `failure` заставляет сторож
сообщать о поломке, которая через полчаса вылечится сама.

**Конфигурация запуска — в `/etc/ai-dev-daily/ai-dev-daily.env`**, не в crontab и
не в репозитории. В файле только **имена** секретов, значения отдаёт Key Vault.
Имена не коммитим намеренно: это карта инфраструктуры. Шаблон — `.env.example`.
Раньше всё это жило одной длинной строкой crontab; с тремя заходами она
размножилась бы втрое, и расхождения между копиями никто бы не заметил.

`CRON_TZ=UTC` обязателен и должен стоять **непосредственно перед** задачей:
переменные времени в crontab действуют до следующего переопределения, и строка,
добавленная после чужого `TZ=...`, унаследует чужую зону.

`config.py` **не читает `.env` сам** — окружение готовит обёртка через `set -a`.
Интерактивной сессии в cron нет, поэтому вход в Key Vault должен быть
non-interactive: **managed identity** на хосте (наш вариант) или service principal.

**Ротация логов** — `ops/logrotate-ai-dev-daily`, ставится в `/etc/logrotate.d/`.
Без неё оба журнала (свой и cron-перенаправление) растут бесконечно.
⚠️ Комментарий в конце строки директивы logrotate ломает правило целиком и
**молча** — проверять только через `sudo logrotate --debug`.

Проверять установку нужно запуском в cron-подобном окружении, а не обычным
shell — иначе не видно, что задаче не хватает PATH или доступа:

```bash
env -i HOME=$HOME PATH=/usr/local/bin:/usr/bin:/bin /bin/bash -c '<строка из crontab> --dry-run'
```

## Поведение при сбоях

| Что случилось | Как ведёт себя сервис |
|---|---|
| Отвалился один источник сбора | Продолжает на оставшихся; упали все — падает с алёртом. Источник, давший **ноль** материалов, уходит отдельным уведомлением владельцу: иначе протухший ключ живёт месяцами, а пост просто выходит беднее |
| Разовый сбой всего прогона | Три захода за утро (04:00 / 04:30 / 05:00 UTC); шумит только последний |
| Истекает GitHub PAT | Предупреждение владельцу за 14 дней. Остальные ключи срока не объявляют — их протухание ловится строкой выше, но уже постфактум |
| Разовый сетевой сбой при сборе и курации | Ретраи с нарастающей паузой, и только потом деградация |
| Разовый сетевой сбой при отправке | Повтор только если соединение не состоялось. Потерянный ответ не повторяем: пост мог уйти, и повтор дал бы дубль |
| Недоступен Perplexity | Курирует на своих кандидатах, помечает дайджест как degraded |
| Недоступен Claude | Ничего не отправляет, падает с ненулевым кодом и шлёт алёрт |
| Процесс погиб сразу после отправки | Следующий запуск видит незакрытое намерение и не шлёт дубль |
| Битый журнал отправок | Уводит в `.corrupt`, продолжает с чистого, сообщает в лог |
| Прошлый прогон завис | Lock мёртвого владельца перехватывается; у живого не отбирается никогда, но приходит алёрт «вмешайтесь» |
| Cron не запустился вовсе | Записывать отметку в этом случае некому, поэтому ловится снаружи: `server-watchdog` алёртит, когда `data/heartbeat.json` отсутствует или старше суток. ✅ Чек **включён 2026-08-14** и проверен обоими исходами (issue #5). Мёртвый хост целиком по-прежнему не покрыт: сторож живёт на том же mh-central — issue #4 |
| Прогон завис и снят внешним `timeout` | SIGTERM превращается в исключение, дальше обычный путь провала: отметка `failure` + алёрт. Без этого снятие по таймауту проходило бы молча — Python на SIGTERM умирает, не выполняя `except` |

Ошибки уходят в Sentry (release тегируется по git sha). Подключение
best-effort: без DSN или при недоступном Sentry сервис работает как обычно.

## Секреты и конфигурация

Значений ключей в репозитории нет и быть не может. `pipeline/config.py` разрешает каждый
секрет так: сначала одноимённая переменная окружения (готовое значение — для локального
прогона), иначе — Azure Key Vault, где хранилище задаётся `KEYVAULT_NAME`, а имя секрета —
переменной `<KEY>_SECRET`. Полный список переменных — в `.env.example`.

| Назначение | Логический ключ |
|---|---|
| X.com recent search | `X_BEARER_TOKEN` |
| Exa neural search | `EXA_API_KEY` |
| GitHub search | `GITHUB_TOKEN` |
| Курация: добор свежего (Perplexity) | `PERPLEXITY_API_KEY` |
| Курация: отбор и тексты (Claude) | `ANTHROPIC_API_KEY` |
| Доставка дайджеста (адресат читателя) | `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` |
| Доставка аварий (адресат владельца) | `TELEGRAM_ALERT_BOT_TOKEN` + `TELEGRAM_ALERT_CHAT_ID` |
| Трекинг ошибок (необязательно) | `SENTRY_DSN` |

**Адресаты разведены намеренно.** Пока дайджест шёл в личный чат, авария в том
же чате была уместна. С переездом в общую группу сообщение «⚠️ Дайджест не
отправлен» стало бы публикацией на глазах у подписчиков. Оба алёрт-ключа
**необязательны**: без них поведение прежнее — аварии идут туда же, куда пост.
Отдельный бот для аварий нужен потому, что бот канала не вправе писать
владельцу в личку, пока тот не нажал Start; развилка снимает эту зависимость
от ручного действия человека.

## Решения по подаче (зафиксировано в сессии 19.07.2026)

- **Голос Армана** (`arman_style.md`): просто, коротко, от первого лица, без пафоса.
- **Личный канал** — без самопредставления («Это Арман» убрано).
- **Через выгоду** — каждый пункт отвечает «что вам это даёт»: применю в деле / научусь / сэкономлю.
- **Без концовки-вопроса и подписи** — финал на выгодном призыве к действию.

## Принятые решения по сервису

| Развилка | Решение |
|---|---|
| Время отправки | 09:00 Астаны = 04:00 UTC |
