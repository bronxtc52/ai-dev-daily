## Часть A — сервис `ai-dev-daily` (Python)

**A1. `pipeline/run_daily.py`: запись heartbeat.**
Функция `write_heartbeat(status, digest_date, reason=None)`:
- пишет `DATA_DIR/heartbeat.json` через существующий атомарный путь (`.tmp` + `os.replace`);
- поля: `status` (`success`/`failure`), `finished_at` (UTC ISO-8601, `Z`), `digest_date`,
  `reason` (только для failure, прогнан через санитайзер секретов);
- **весь вызов в своём `try/except`** — heartbeat не имеет права уронить прогон (критерий 5);
- в `--dry-run` не вызывается вовсе (критерий 3).

**A2. Точка вызова — одна, в `main()`, по коду возврата.** Разведка кода поправила
первоначальный замысел: `run()` возвращает **четыре** кода, и часть провалов — не
исключения, а `return`. Вешать heartbeat на `except` значило бы пропустить их молча
(например, `return 1` «в пост влезло меньше минимума блоков» — дайджест не вышел, а
монитор увидел бы тишину, неотличимую от успеха).

| Код `run()` | Смысл | heartbeat |
|---|---|---|
| 0 | отправлено (или сегодня уже отправляли) | `success` |
| 1 | провал без исключения (мало блоков после усечения) | `failure` |
| 3 | неразрешённое намерение — молчим до завтра | `failure` |
| 2 | занят lock: работает ДРУГОЙ прогон | **не пишем вовсе** |
| исключение | падение | `failure`, **до** `_try_alert` (критерий 2) |

Код 2 — намеренное исключение: писать за чужой прогон нельзя, свой исход этому процессу
неизвестен. Настоящий владелец lock'а запишет сам, а если он завис — его поймает тот же
порог свежести.

**A3. `.gitignore` + README.** `data/heartbeat.json` — состояние прогона, в git не едет.
Строка в таблицу «Поведение при сбоях»: «Cron не запустился вовсе → ловит сторож».

## Часть B — сторож `server-watchdog` (TypeScript)

**B1. `src/types.ts`.** `AiDevDailyReport { enabled, present, status, ageHours, finishedAt,
path, errors }` + поле в `ServerReport` + три поля в `RuntimeConfig`.

**B2. `src/config.ts`.** `aiDevDailyEnabled` (`=== 'true'`, деф. false),
`aiDevDailyHeartbeatPath` (деф. `/home/azureuser/projects/ai-dev-daily/data/heartbeat.json`),
`aiDevDailyMaxAgeHours` (`parseNonNegativeNumber`, деф. 26).

**B3. `src/collectors/aiDevDailyHeartbeat.ts`.** Синхронный `readFileSync` + `JSON.parse`
в `try/catch`. Возраст считаем **по `finished_at` из тела**, а не по mtime файла: mtime
переживает `cp -p`/rsync и врёт при переносе состояния, а поле пишет сам прогон.
Разведены три исхода: нет файла (ENOENT) → `present=false` без ошибки; битый JSON /
нечитаемое `finished_at` / чужой `status` → `errors[]` (критерий 11); валидный → поля.
`status` нормализуем строгим списком: неизвестное значение = ошибка, не «успех».

**B4. `src/analyzers/findings.ts`.** Функция `analyzeAiDevDailyFindings`, врезанная в
**обе** ветки. Три замороженные формулировки, severity `warning` (сервис не
пользовательский — крит каждые 6 ч обесценил бы крит как класс, урок configWarnings #76):

| Условие | Строка |
|---|---|
| нет файла ИЛИ возраст > порога | `ai-dev-daily: утренний дайджест не выходил больше суток — прогон не состоялся` |
| свежий, `status=failure` | `ai-dev-daily: последний прогон дайджеста завершился ошибкой` |
| ошибка чтения/разбора | `ai-dev-daily: heartbeat не читается — состояние сервиса неизвестно` |

Ни одного меняющегося числа в тексте (критерий 14). `reason` из heartbeat **не печатаем**:
чужой текст ломает фингерпринт и тащит неконтролируемый egress (правило из `systemd.ts`).

**B5. `src/index.ts`.** `config.aiDevDailyEnabled ? collectAiDevDaily(config) : undefined`
+ условный attach в отчёт (выключенный чек поля не кладёт — критерий 12).

**B6. `src/collectors/CLAUDE.md`.** Абзац по конвенции репо: что ловим, почему по
`finished_at` а не mtime, почему 26 ч, почему без чисел в тексте, флаги, notify-only.

## Тесты (Шаг 3, red-first)

Сервис (`pytest`, файл `tests/test_heartbeat.py`): success пишет файл с полями; failure
пишет `status=failure` до алёрта; `--dry-run` файл не создаёт и существующий не трогает;
секрет из текста исключения в файл не попадает; падение записи не роняет прогон.
Негативные проверки — с обязательным доказательством непустоты артефакта (урок
`logging-basicconfig-noop-and-hollow-tests`: «в файле нет X» на пустом файле всегда зелено).

Сторож (`node:test`, `aiDevDailyHeartbeat.test.ts`): свежий success → ноль issues;
возраст 27 ч → ровно одна строка; файла нет → одна строка; битый JSON → строка «не
читается»; `status` из будущего (`"skipped"`) → строка ошибки, НЕ тишина; выключенный
флаг → коллектор не зовётся, поля нет; порог из конфига уважается. Время и fs
инъектируются (`deps`), реальная ФС не трогается.

## Правки по итогам внешнего ревью плана (council quick, 3/3 кандидата, 2026-08-12)

Вердикт `UNVERIFIED` (прогон без веб-проверки) — совещательный. Принято к исполнению:

1. **Порог 26 ч был арифметически неверен** — главная находка. Отметка ставится на
   завершение (~04:01), значит в 06:00 её возраст 25 ч 59 мин, и порог 26 ч не срабатывал
   бы: алёрт уезжал на 12:00 UTC, латентность ~8 ч вместо обещанных ~2 ч. Порог **24 ч**,
   арифметика с обеими границами — в ТЗ, тест на обе стороны порога — обязателен.
2. **Отметка называет себя** (`service="ai-dev-daily"`). Опечатка в пути могла привести
   коллектор к чужому валидному JSON со `status` внутри — вечная тишина при исправном виде.
3. **`NaN`/пустое/будущее время — ошибка, не свежесть.** `NaN > threshold` даёт `false`,
   то есть наивная реализация молчала бы именно там, где должна кричать.
4. **Статус — точный список в нижнем регистре**; `"Success"`, `null`, `""` → ошибка.
5. **`EACCES` ≠ `ENOENT`** — разные строки, обе не тишина.
6. **Изоляция сбоя коллектора** от остального дайджеста — отдельным тестом.
7. **Дефолт «выключено» — тестом**, чтобы будущий рефактор конфига не включил чек везде.
8. **Состав отчёта** сузить осознанно: `reason` из heartbeat в отчёт **не кладём** —
   он идёт в AI-анализатор (внешний egress), а свободный текст туда не отдаём.
9. Эскалацию класса M→L объявляю открыто, а не тихо (сделано в чате до кода).

Не принято: снижать порог до 25–25.5 ч — 24 ч даёт больший запас на стороне, где цена
ошибки выше (пропущенный алёрт хуже лишнего), а верхний запас защищён потолком прогона.

## Риски и как закрыты

- **Сломать общий сторож.** Чек за kill-switch (деф. false) — до включения флага код
  не исполняется вовсе; коллектор не бросает наружу (весь ввод-вывод в try/catch);
  `tsc --noEmit` + полный прогон тестов репо до PR.
- **Ложная тишина.** Все неопределённости (битый файл, чужой статус, нечитаемое время)
  ведут к алёрту, а не к молчанию.
- **Ложный шум.** Порог 26 ч + отсутствие чисел в тексте + kill-switch.
- **Не покрыто (осознанно):** мёртвый хост целиком. Остаётся в issue #2 с новым триггером.
