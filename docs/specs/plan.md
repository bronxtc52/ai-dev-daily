# План реализации: ai-dev-daily как автономный сервис

_armanda v2.3.0, Шаг 2. ТЗ: `daily-service.md`. Класс: **L** (новая рантайм-зависимость
Perplexity + 3 новых модуля + оркестратор). Риск-триггер: чтение Key Vault._

## Факты из живой разведки API (2026-08-11, не из памяти)

| Факт | Следствие для кода |
|---|---|
| У Perplexity есть `search_results` (20 шт.: `title`, `url`, `date`, `snippet`, `last_updated`) | Парсим их, а не `citations` (там голые URL без метаданных) |
| `usage.cost.request_cost = $0.005` — почти вся цена **фиксированная за запрос**, не за токены | Экономим на ЧИСЛЕ запросов: 2 широких вместо 4 узких (~$0.01/день) |
| usage-заголовков в HTTP нет, стоимость только в теле ответа | Учёт расходов читаем из `data["usage"]["cost"]`, не из заголовков |
| Ответ Perplexity содержит `**` и `- ` | Санитайзер обязателен — подтверждено на живом ответе, не гипотеза |
| `claude-sonnet-5` и `claude-opus-5` доступны, формат `/v1/messages` стандартный | Курация на `claude-sonnet-5` |

## Архитектура

```
pipeline/
  config.py      (есть)  секреты: env → Key Vault
  collect.py     (правка) сбор X/Exa/GitHub, окно от now(utc)
  curate.py      (новый)  Perplexity добор + Claude отбор → digest.json
  dedup.py       (новый)  sent_history.json, нормализация URL
  format.py      (новый)  md_to_telegram_html, сборка поста, усечение
  send_post.py   (рефактор) читает digest.json, без вшитых литералов
  run_daily.py   (новый)  оркестратор + уведомление о сбое
tests/           (новые)  по критериям приёмки ТЗ
```

Поток: `collect → dedup(pre) → curate → dedup(post) → format → send → history.append`

Дедуп стоит **дважды**: до курации (не платим Claude за уже отправленное) и после
(страховка от материала, который Perplexity добрал в обход первого фильтра).

## Ключевые решения

1. **Claude отдаёт строгий JSON**, а не свободный текст: схема `{blocks:[{emoji,title,url,
   benefit}], radar:[{title,url,note}]}`. Ответ валидируем; невалидный → 1 ретрай с
   сообщением об ошибке → при повторном провале падаем (критерий 9), а не шлём мусор.
2. **Нормализация URL** для дедупа: схема → https, host → lower + срез `www.`,
   срез трекинг-параметров (`utm_*`, `fbclid`, `gclid`, `ref`), срез конечного слеша,
   срез `#fragment`. Покрывает критерий 6.
3. **Атомарная запись состояния**: пишем в `<file>.tmp` + `os.replace()`. Иначе краш
   посреди записи оставит битый `sent_history.json` и снесёт всю историю дедупа.
4. **Блокировка от параллельного запуска**: `fcntl.flock` на lock-файле. Cron может
   наложиться на ручной запуск — без блокировки получим два поста и гонку за историю.
5. **Идемпотентность за день** (критерий 10): в `sent_history.json` хранится
   `last_sent_date`; повторный запуск в ту же дату выходит с кодом 0 и ничего не шлёт.
   Флаг `--force` для ручного переопределения.
6. **Усечение** (критерий 7): режем по границам блоков, а не по символам. Лимит 4096;
   при переполнении выбрасываем блоки с конца, «на радаре» — первым кандидатом на вылет.
7. **Деградация Perplexity** (критерий 8): исключение/таймаут → лог WARNING, курация
   идёт на одних кандидатах из `collect.py`. Утренний пост важнее полноты.
8. **Уведомление о сбое** (критерий 9): `run_daily.py` ловит исключение верхнего уровня
   и шлёт короткий plain-text алёрт в тот же чат. Отправка алёрта — в своём try/except,
   чтобы падение алёрта не маскировало исходную ошибку.
9. **Секреты в логах** (критерий 11): логгер настроен на именованные поля; ни один
   `except` не печатает тело запроса. Тест грепает лог прогона на подстроки ключей.

## Порядок работ (TDD)

1. Тесты по критериям 1–11 → красные → отдельный коммит.
2. `format.py` (санитайзер из KB + сборка + усечение) — критерии 2,3,4,7.
3. `dedup.py` (нормализация + история + атомарная запись) — критерии 5,6.
4. `collect.py` — правка окна времени — критерий 1.
5. `curate.py` (Perplexity + Claude, деградация) — критерии 8,9.
6. `send_post.py` рефактор + `run_daily.py` — критерии 10,11.
7. Зелёный прогон, ревью, приёмка.

## Границы (из ТЗ, повторно)

Выкат на mh-central и создание секретов `ai-dev-daily--*` — **не в этой задаче**,
отдельным шагом с отдельным подтверждением. В этой задаче Key Vault только читается.

## Правки по итогам внешнего ревью (council quick, 3/3 кандидата, 2026-08-11)

Вердикт `UNVERIFIED` (прогон без веб-проверки) — совещательный. Принято к исполнению:

1. **Идемпотентность: crash-after-send.** Решение №5 выше недостаточно — оно ловит только
   штатный повтор. Подтверждение отправки (`message_id`, hash дайджеста, `sent_at`)
   пишется атомарно **сразу после успешного ответа Telegram**, до любых последующих
   шагов. Иначе падение между отправкой и записью истории даёт дубль утром.
2. **Абсолютные пути.** `DATA_DIR`, лог и lock-файл резолвятся от корня репозитория, а не
   от `cwd`. Под cron относительный путь к `sent_history.json` увёл бы дедуп в другую
   директорию — молча, без ошибки, то есть критерий 9 бы не сработал.
3. **Retry с backoff до деградации.** Разовый таймаут или 5xx не должен переводить сервис
   в постоянную деградацию: 2 ретрая с экспоненциальной паузой, и только потом решение
   «деградировать/падать». (Подтверждено на живом примере: сам совет упал транзиентной
   `APIConnectionError` и отработал со второй попытки.)
4. **Таймауты как числа.** На каждый HTTP-вызов и общий потолок на прогон
   (`run_daily.py` — 10 минут). Зависший процесс — это тишина без ошибки: алёрт не уйдёт.
5. **Атомарность для всех файлов состояния**, не только для истории: `digest.json` и
   lock тоже. Плюс политика на битый `sent_history.json`: не падать молча и не терять
   историю — уводить в `.corrupt` и начинать новую, сообщив об этом.
6. **Stale lock.** Lock хранит pid и время; лежащий дольше потолка прогона считается
   протухшим и перехватывается, иначе один зависший процесс убьёт все следующие утра.
7. **Смоук-проверка дайджеста.** 3–6 блоков, у каждого валидная URL-схема. Иначе Claude
   вернёт 1 или 15 блоков, и это пройдёт мимо всех текущих критериев.
8. **Алёрт о сбое не должен нести секретов.** В текст исключения от провайдера легко
   попадает URL с ключом в query — алёрт санитизируется отдельно, прицельным тестом.
9. **Prompt injection из источников.** Заголовки и сниппеты приходят из интернета и
   уходят в Claude. Внешний контент — данные, не инструкции: кандидаты передаются
   размеченным блоком с явной инструкцией игнорировать любые команды внутри них.
10. **Частичный отказ источников.** Политика зафиксирована явно: сбор продолжается на
    частичных данных, если жив хотя бы один источник; ноль живых — падение с алёртом.
11. **Нормализация URL — только домен в нижний регистр**, путь не трогаем: у части
    сайтов путь регистрозависим, и `lower()` по всему URL сломал бы ссылку.
12. **Режим `--dry-run`** — полный прогон без отправки, для проверки после деплоя.

### Отложено с триггером (вне границ задачи)

- **Внешний heartbeat «cron не запустился вообще»** — уведомление о сбое ловит только
  упавший процесс, но не отсутствие процесса (сервер спал, cron не сработал, venv сломан).
  Закрывается сторожем на стороне мониторинга. Триггер возврата: выкат сервиса на сервер.
- **Механизм авторизации к Key Vault из-под cron** — `az` в cron не имеет интерактивной
  сессии. Решается на шаге деплоя: либо заранее собранный `.env` (как у соседних
  cron-сервисов), либо service principal. `config.py` уже поддерживает оба пути, менять
  код не потребуется. Триггер возврата: шаг деплоя.

## Открытые риски

- **Качество курации не покрывается автотестом** — «хороший отбор» не выражается
  критерием да/нет. Проверяем глазами на первом реальном прогоне.
- **Расход**: Perplexity ~$0.01/день + Claude ~$0.02/день ≈ **$1/мес**. Кап на число
  запросов вшит в код (2 к Perplexity, 1 к Claude за прогон).
- **Cron на mh-central** не даёт автоматического алёрта на «прогон не состоялся вообще»
  (машина спала, cron не сработал). Уведомление о сбое ловит только упавший прогон.
  Кандидат на heartbeat в server-watchdog — вне границ этой задачи.
