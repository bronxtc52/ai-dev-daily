# ТЗ: превращение разовых скриптов в боевой сервис

_Составлено 2026-08-11, конвейер armanda v2.3.0. Подтверждено пользователем._

## Цель

Пробный прогон 19.07.2026 состоял из скриптов, в которых зашиты дата и текст поста,
а курация делалась вручную. Задача — довести пайплайн до состояния, когда он
отрабатывает по расписанию **без человека**: сам собирает, сам отбирает, сам пишет
пост, сам не повторяется и сам сообщает о провале.

## Решения пользователя (зафиксированы 2026-08-11)

| Развилка | Решение |
|---|---|
| Движок курации | **Perplexity (добор свежего с источниками) + Claude (фильтр и текст)** |
| Где крутится | **cron на mh-central** (не ACA → правило «прод только через CI» не применяется) |
| Время отправки | **09:00 Астаны = 04:00 UTC** |
| Namespace ключей | **свой `ai-dev-daily--*`** в Key Vault (создание секретов санкционировано) |

## User stories

1. Утром в 09:00 я получаю в Telegram дайджест из 3–6 материалов, где каждый пункт
   отвечает «что вам это даёт», — без моего участия.
2. Я не вижу дважды один и тот же материал, даже если источники подняли его повторно.
3. Если ночью что-то отвалилось, я узнаю об этом из сообщения о сбое, а не по тишине.

## Scope

1. **`collect.py`** — окно свежести от `datetime.now(timezone.utc)`; глубина окна
   параметром (по умолчанию 3 дня). Убрать константу `datetime(2026,7,19)`.
2. **`curate.py`** (новый) — двухступенчатая курация:
   - Perplexity: добор свежих фактов с источниками по темам из `prompt.md`;
   - Claude: отбор по критериям и анти-фильтру `prompt.md`, ранжирование,
     генерация текста блоков в голосе из `arman_style.md` (подача через выгоду);
   - выход — `data/digest-YYYY-MM-DD.json` (структура: блоки + «на радаре»).
3. **Дедуп** — `data/sent_history.json`: нормализованный URL + дата отправки,
   окно 30 дней. Отправленное раньше в новый дайджест не попадает.
4. **`send_post.py`** — генератор поста из `digest.json` вместо вшитых литералов.
   Весь LLM-текст проходит `md_to_telegram_html` (референс из knowledge-base,
   `snippets/telegram-llm-markdown-to-html.md`), усечение — по границам строк.
5. **`run_daily.py`** — оркестратор `collect → curate → dedup → send`, логи,
   осмысленные коды возврата, уведомление о сбое в тот же Telegram.
6. **Тесты** по критериям приёмки ниже.
7. **Деплой-артефакты**: строка crontab, инструкция установки в README,
   дополненный `.env.example`.

## Границы — что НЕ делаем

- **Не выкатываем на mh-central** в рамках этой задачи. Выкат и создание секретов
  `ai-dev-daily--*` — отдельным финальным шагом с отдельным подтверждением.
- Не заводим Email-канал (развилка №3 закрыта в пользу Telegram).
- Не переписываем `prompt.md` и `sources.md` по существу.
- Никакой БД и веб-интерфейса: состояние — файлы в `data/`.
- Не трогаем чужие проекты и их секреты.

## Критерии приёмки (проверяемые да/нет)

| # | Критерий |
|---|---|
| 1 | `collect.py` берёт окно от текущего UTC-времени: при подменённом «сейчас» `since_date` равен ожидаемому; константы `2026,7,19` в коде нет |
| 2 | `**жирный**` от LLM превращается в `<b>жирный</b>`, а не уходит звёздочками |
| 3 | Текст с сырым `<` (например «латентность <3,0 с») доставляется, парсер не падает: `html.escape` применён ДО конвертации markdown |
| 4 | `snake_case_name` не превращается в курсив (lookaround на `_`) |
| 5 | URL, отправленный в пределах 30 дней, во второй дайджест не попадает |
| 6 | Разные формы одного URL (utm-хвост, конечный слеш, http/https) считаются одним материалом |
| 7 | Пост длиннее лимита Telegram (4096) режется по границам строк; ни один HTML-тег не разорван |
| 8 | При недоступности Perplexity `curate.py` деградирует на «только Claude» и отдаёт валидный дайджест |
| 9 | При недоступности Claude `run_daily.py` не шлёт пустой пост, а падает с ненулевым кодом и сообщает о сбое |
| 10 | Повторный запуск в тот же день не отправляет дубль |
| 11 | Значения секретов не попадают в логи и в stdout ни на одном пути (включая пути ошибок) |

### Добавлено после внешнего ревью плана (council, 2026-08-11)

| # | Критерий |
|---|---|
| 12 | Падение между успешной отправкой и записью истории не приводит к дублю: отметка об отправке пишется сразу после ответа Telegram, и следующий запуск её видит |
| 13 | Прогон из произвольного `cwd` работает: пути к `data/`, логу и lock резолвятся от корня репозитория |
| 14 | Разовый сетевой сбой не уводит в деградацию: при первом провале идёт ретрай, деградация — только после исчерпания попыток |
| 15 | Дайджест перед отправкой проходит смоук: 3–6 блоков, у каждого валидная схема URL; иначе отправки нет |
| 16 | Текст алёрта о сбое не содержит значений секретов, даже если исключение провайдера включало URL с ключом |
| 17 | Битый `sent_history.json` не роняет прогон молча и не теряется: файл уводится в `.corrupt`, работа продолжается с новой историей |
| 18 | Lock мёртвого владельца перехватывается. Lock ЖИВОГО процесса не отбирается никогда — даже если тот висит дольше потолка: два параллельных прогона хуже пропущенного утра. Про висящий владелец уходит алёрт, тишины нет |
| 19 | Инструкции внутри внешнего контента (заголовков, сниппетов) не исполняются моделью: кандидаты уходят размеченным блоком данных |
| 20 | `--dry-run` проходит весь путь и ничего не отправляет |

## Допущения (беру дефолтом, поправьте если не так)

- **Модель курации** — `claude-sonnet-5`: ежедневная рутина отбора, где Opus избыточен.
- **Perplexity** вызывается из кода напрямую (HTTP API, ключ из Key Vault), а не через
  CLI-обёртку `pplx` — та инструмент разработки, а не рантайм-зависимость сервиса.
- **Окно дедупа** — 30 дней; **глубина сбора** — 3 дня.
- **Уведомление о сбое** идёт в тот же Telegram-чат, что и дайджест.
- Живой вызов Perplexity и Anthropic делаю **до** написания кода и фикстуры снимаю с
  реальных ответов (урок KB `lessons/provider-billing-api-drift-verify-live.md`:
  Perplexity молча убрал usage-заголовки и требует `max_tokens >= 16`).

## Класс задачи

**L** — переклассифицировано на Шаге 2. Изначально оценил как M, но Perplexity
становится новой рантайм-зависимостью сервиса, плюс появляются три новых модуля и
оркестратор; правило «сомневаешься между двумя — бери больший» указывает туда же.
Следствие: план прошёл внешний челлендж советом, дифф — независимое ревью.
